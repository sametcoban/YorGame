# Ashbound — The Last Oathkeeper

An original dark fantasy arcade brawler inspired by directional timing games. A cursed knight holds a ruined graveyard causeway against an endless procession of skeletons and wraiths. All scenery, characters, effects, and audio are generated by the project; there are no purchased assets or external asset downloads.

## Open and play in Unity 6

1. In Unity Hub, choose **Add → Add project from disk** and select the **Ashbound** folder beside this README. Do not select the parent `YorGame` folder.
2. Open it using your installed **Unity 6** Editor. The version recorded in the project is `6000.0.65f1`; Hub may ask you to select your installed Unity 6 version if it differs.
3. Choose **Ashbound → Open Arena**, or open `Assets/Ashbound/Scenes/Arena.unity`.
4. In the **Game** view, select a landscape aspect ratio such as **16:9** and press **Play**.
5. Click **TAKE THE OATH** or press **Enter**.

The scene looks empty in Edit mode. The runtime bootstrap constructs the entire arena and user interface when Play starts. Use the built-in render pipeline; this prototype does not require URP or HDRP.

If Hub says **Please add a valid project**, extract the ZIP first and select the folder that directly contains **Assets**, **Packages**, and **ProjectSettings**. Do not select the ZIP, an outer download folder, `Assets`, or the original `YorGame` repository root. The `Ashbound-6000.0.65f1.zip` download places those three directories directly at the archive root, so select the folder created by **Extract All**. With a GitHub download of this repository, select its **Ashbound** subfolder as the Unity project.

## Controls and rules

| Action | Keyboard | Mouse / mobile touch |
| --- | --- | --- |
| Strike left | A or Left Arrow | Click / tap the left half |
| Strike right | D or Right Arrow | Click / tap the right half |
| Ultimate left | Q | WAVE LEFT button beneath the ultimate meter |
| Ultimate right | E | WAVE RIGHT button beneath the ultimate meter |
| Start / retry | Enter or Space | On-screen button |
| Pause / resume | P or Escape | Top-right pause / resume button |
| Toggle audio | M | SOUND button |

Strike the side of the **nearest enemy**. Enemies hold their places in a six-enemy approach queue instead of walking continuously. Every accepted normal attack advances them: a kill makes survivors step forward and adds a replacement at the back; a miss pushes the existing enemies closer without refilling the queue. The front enemy then makes contact and deals one wound. Only the front enemy is in range; striking the other side misses. Every enemy takes one hit; wraiths are a visual variant introduced after 22 seconds. Attacks have a short cooldown and do not repeat when held; cooldown-rejected clicks do not cause additional movement or damage.

Each accepted normal attack cycles **cleave → rising cut → thrust → spinning slash**, then repeats. Each style has its own sword path, body movement, and foot stance, mirrored toward the selected side. Misses still advance the animation cycle; presses rejected during cooldown do not. The kill-chain score is independent of this four-attack animation sequence. The ultimate has its own heavy swing and does not advance the normal attack cycle.

- A kill earns **100 souls**. Responding within **0.3 seconds** of the queue advancing earns **PERFECT**, worth **150 souls**.
- Every ten consecutive kills raises the multiplier, up to **x5**. Missing or being wounded breaks the chain.
- Every defeated enemy adds **2.5 ultimate charge**, capped at **100**. Forty kills fill an empty meter; misses and wounds do not drain it.
- At 100, press **Q** for left or **E** for right, or tap the matching **WAVE** button. **Oathbreaker** instantly clears all enemies currently on the chosen side, at any distance, and sends a large gold-and-teal crescent across the arena with trailing slashes, soul bursts, a brief flash, screen shake, and a distinct sound. Opposite-side enemies survive and step forward to close the gaps. The next normal kill replenishes the queue so the cleared side stays visibly empty during the cast.
- Casting spends 100 charge, including when the selected side is empty. Wave kills award normal souls and combos and each return 2.5 charge toward the next ultimate. New runs start with zero charge. The ultimate can interrupt a normal sword attack.
- You have **three wounds**. A response bar shows how long remains to strike. If it expires, the front enemy lands one wound and the next enemy takes its place with a fresh deadline. Misses advance enemies, break your combo, and do not reset the clock or award souls, kills, or ultimate charge. A correct follow-up resumes normal queue replenishment and resets the response clock.
- Each night lasts 20 seconds. The response window starts at roughly **1.6 seconds**, tightening to **0.55 seconds** over about 90 seconds. Successful kills reset it; you control the pace, with no timed-spawn wait between kills. There is a brief opening grace period before the first queue appears.
- The highest completed-run score and audio / screen-shake preferences are saved locally with PlayerPrefs.
- Losing focus or backgrounding the app pauses an active run. Screen shake can be disabled from the pause menu.

## Build on your machine

**Desktop:** choose **Ashbound → Build → Desktop**. This builds for your current Editor OS into `Builds/Windows`, `Builds/macOS`, or `Builds/Linux`. Install the corresponding build module in Unity Hub if requested.

**Android:** install **Android Build Support**, including SDK, NDK, and OpenJDK, for your Unity Editor through Unity Hub. Choose **Ashbound → Build → Android APK**. The menu sets ARM64 and IL2CPP and writes `Builds/Android/Ashbound.apk`. This is a development prototype using the default debug signing; store publishing requires your own application ID, release signing, icons, and device validation.

The project uses Unity's legacy Input API for keyboard, mouse, and touch. **Active Input Handling** is set to **Input Manager (Old)**. If you change that setting, keep legacy input enabled. Portrait layouts, iOS builds, and production mobile performance have not been validated.

## Development

The existing `YorGame.sln` and `Data.Layer` library are independent and unchanged. Unity generates its own solution files under this folder.

- `Assets/Ashbound/Scripts/Core/CombatSession.cs`: deterministic, engine-independent combat model. Timing, health, scoring, spawning, and cooldown constants live here.
- `Assets/Ashbound/Scripts/Runtime/AshboundGame.cs`: scene startup, input, run state, feedback, and presentation synchronization.
- `ArenaBuilder.cs` / `CharacterView.cs`: procedural environment, characters, and animation.
- `GameHud.cs` / `AudioDirector.cs`: scalable IMGUI screens and generated sound cues.
- `Assets/Ashbound/Editor/AshboundMenus.cs`: scene and build menus.
- `Assets/Ashbound/Resources`: material templates that retain the required Standard shader variants in builds.

The combat simulation uses game time; pausing does not advance it. There are no backend services, accounts, secret keys, networking, or monetization integrations.

## Validation

With Mono (`mcs` and `mono`) installed, run from this project folder:

```bash
bash Tools/test-combat.sh
```

The script also supports the cloud environment's Mono installation automatically. Its output and compiled runner go into ignored `Artifacts/CombatTests/`. The dependency-free suite covers opening grace, range, response-based perfect strikes, incorrect-side attacks, cooldowns, defeat, reset, deterministic encounters, wraith introduction, three minutes of automated survival and score scaling, immediate target availability, frame hitches, invalid inputs, exact ultimate charging and its cap, both directional clears, range independence, wave rewards, attack interrupts, empty casts, charge reset, the four-attack style cycle, stationary enemies between attacks, one-step advances, miss contact damage and defeat, cooldown-safe punishment, recovery after misses, timeout damage, post-ultimate queue compaction, and empty-queue recovery.

With Python 3, run `python3 Tools/check-asset-guids.py` to check the length and format of asset GUIDs, duplicate identities, and serialized references in materials, scenes, and settings. This catches malformed built-in shader references that a C# compilation cannot detect.

**Verified in the cloud:** all 34 combat regression tests passed. A fast-input simulation sustained a maximum gap of 0.18 seconds between kills after the opening ten seconds, with no player damage or waits for timed spawns. The asset GUID check passed, and updated Core and Runtime C# compiled against Unity 2022.3 reference assemblies as an API compatibility check. No Unity Editor was available here, so Unity 6 import, Play mode rendering / audio / touch input, stepping and attack animations, ultimate effects, the Editor build menus, and actual desktop / Android builds still need validation on your machine. The compatibility compile does not replace those checks.

For the first Editor check, confirm the title appears without Console errors, start a run, and check that enemies hold still between attacks. Each kill should produce a quick step, a replacement at the back, and another reachable enemy. Strike the wrong side and confirm enemies step closer, the front enemy deals one wound, and the response deadline stays unchanged; let the clock expire and confirm one wound and a fresh deadline. Pause/resume and retry. Cycle attacks and check the downward cleave, rising cut, forward thrust, and full-body spin, plus the return to the ready stance. Confirm each kill adds 2.5 to the ultimate meter; after 40 kills, cast with Q or E and check the hero's heavy swing, three-layer crescent, soul bursts, sound, flash, and chosen-side clear. Check that opposite-side enemies survive and step forward safely, wave kills recharge the meter, normal kills resume replenishment, and retry resets charge and the queue. On a device, also test both touch halves, both WAVE buttons (including that uncharged buttons do not cause a regular attack), the sound / pause buttons, background/resume, and the safe-area layout.

This is a first playable implementation with procedural placeholder art, not a finished commercial game.
